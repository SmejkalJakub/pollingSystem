## Organizer workflow

Open **Příprava → Kategorie → Nové hlasování**, or open an existing draft. One form contains name/instructions, selection/final type, explicit D21 limits, T/V checkboxes and voting entries. **Uložit kategorii** saves all sections together in one transaction. Any error saves none of that attempt. Inputs and field errors remain available, with a focused linked summary. Pending saves/refreshes pause editing. Authorization loss clears protected content.

A new category can remain an incomplete draft: rules wholly unset, no permitted groups or no entries. Setting or correcting rules requires the existing complete valid four-field tuple. No defaults or formula are inferred. Previously stored rules cannot be cleared through this form; untouched legacy partial tuples can be retained until explicitly corrected. Activation separately enforces candidate counts, complete rules and permissions. The later [2026-10-20 update](event-flexibility.md) removes the equal 5/7/9 jury-size rule and adds bulk team assignment to this form. The form creates no jury groups, shared teams, personal links or sessions.

Add entries by selecting existing event teams, with an explicit nonnegative display order. Equal team names remain distinct IDs and the selector identifies them. Each team may appear once per category. New unsaved entries can be removed locally; saved entries cannot be deleted or omitted. Saved entry IDs survive reassignment and reordering. Unchanged team links retain their stored descriptive snapshots, including when a shared team's current description changes. Untouched unlinked legacy entries may remain until explicitly linked; activation still rejects them.

Activation requires finishing/discarding form edits and remains a separate confirmation. Editing pauses while that confirmation is open. Closing, unconditional reopening, ballot unlocking, current-only results, ties, finality and XLSX retain their existing workflows. Configuration stays frozen after activation or any ballot; reopening never unlocks setup. Other draft categories in a frozen-roster event remain editable under the original category rules.

Save before leaving. Values, new stable IDs and comparison state live in component memory only; no autosave or durable browser draft. A browser unload warning is attempted for dirty values, subject to browser behavior. Cancellation of a new form requires saving or explicitly discarding pending edits first.

## Comparison and retries

**Načíst aktuální přípravu** loads a clean form directly. With dirty values or a conflict it instead keeps local values and displays local/current metadata, rules, permissions and entry IDs for comparison. Applying reviewed changes keeps changed local metadata fields, the whole changed rule tuple/permission selection, and whole changed entry rows. It takes current untouched fields/rows and remote additions. This explicit comparison action never saves; save separately. Another concurrent change can conflict again. An edited externally removed saved entry cannot be recreated; a current freeze disables applying changes. Discard/load current remains available.

One client-generated category UUID is retained throughout new-category retries; each new entry also keeps its UUID. If all normalized desired metadata, rules, permissions and entry IDs/team links/orders already equal stored state, retry confirms the current snapshot without timestamp/history writes. This exact no-write confirmation remains possible after activation/closure, with current administration authorization. Otherwise the exact base fingerprint must match, configuration must still be editable and all saved entry IDs must be retained. An uncertain success followed by a different change requires comparison; no replacement IDs or automatic write retry.

## API and storage

- `GET /events/:eventId/votings/:votingId/setup`: strict empty query; returns `{version,voting,editable,groups,teams,juryGroupIds,items}`. An unused client UUID returns a read-only new-category template with `voting:null`. Existing legacy read/create/PATCH/configuration/group/item endpoints remain compatible.
- `PUT` at the same path: strict `{baseVersion,values:{name,instructions,kind,configuration,juryGroupIds,items:[{id,teamId,displayOrder}]}}`. IDs normalize to lowercase; duplicates, malformed fields and unknown claims reject. Domain-invalid fields return `{status:'invalid',issues:[{field}]}` without writes; success returns `{status:'saved',snapshot}`. The complete request retains the existing 64 KiB limit; oversized input gets 413 and is retained for correction, never partially saved.
- Current administration cookie, same-origin/custom-header and no-store boundaries apply, with authorization after the event-lock wait and before transaction completion. Missing/expired/revoked sessions return 401; juror/forbidden-origin access 403, malformed shape/query 400, missing event 404, changed/omitted/colliding identity `409 VOTING_SETUP_CONFLICT`, frozen writes `409 VOTING_NOT_EDITABLE`, and dependency errors sanitized 503.

The SHA-256 fingerprint includes scoped category data with precise PostgreSQL timestamps, raw entry snapshots, permissions, available event teams/groups and whether this category has ballots. Roster changes alone do not freeze another draft category. Saves share the existing exclusive event-first transaction; reads use its shared lock. Existing legacy writes invalidate snapshots through stored changes. Reassignment swaps temporarily unlink only affected team references inside the transaction to satisfy the existing immediate unique constraint; item IDs and references are never deleted, and any failure rolls all sections back.

No schema, migration, dependency, voting engine, identity, submission/revision/unlock/history, ranking/tie/finality or export change. Category tables/import, bulk personal-link copying, duplication and new readiness tools remain later work requiring a new explicitly user-started session. No commit, push, deployment or cloud/live-data action is authorized here. [Stage 1 external-key/access prerequisites](simplification-stage-1.md) remain authoritative.
